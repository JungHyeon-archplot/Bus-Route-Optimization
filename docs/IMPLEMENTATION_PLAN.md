# 구현 계획

첫 실험은 배차 위상만 바꿉니다. 정류장 통과·속도 변경을 동시에 적용하지 않습니다.

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| 0 | 원본 보존·문서·협업 | 검토 목록, 이슈, PR 템플릿 |
| 1 | 가상 6거점 데이터 | ID·양수 길이·순환 연결 검증, 지명 변경 불변 |
| 2 | 사건 기반 엔진 | FIFO·차량 복귀 제약·누적 기록·동일 조건 |
| 3 | 수학 모듈 | 최단경로·정확 매칭 우체부 순회·일반 색칠 테스트 |
| 4 | 비교 화면 | 동시 재생·배속 독립·가상 표시·CSV/JSON |
| 5 | API 수집 준비 | 서버 키·타임아웃·기관 오류 mock 테스트 |
| 6 | 실측 데이터 | 실제 ID·방향·도로·관측시간 검토 PR |
| 7 | 수요 확장 | 정원·목적지·환승·다중 정차면 검증 |

이번 구현은 0~5단계입니다. 실제 키를 사용한 통합 검증과 6~7단계,
카카오 배경지도·보로노이는 후속 이슈로 관리합니다.

## 구조

Node.js 22 이상, 브라우저 ES modules, SVG 개념도. 외부 패키지 설치 없이 실행합니다.

- src/graph.js: 최단경로·우체부·색칠
- src/simulation.js: 사건 엔진·지표
- src/scenario.js: 가상 데이터·검증
- public/: 화면·애니메이션·다운로드
- scripts/server.mjs: 허용 경로만 제공하는 로컬 서버
- scripts/collect.mjs: 수동 API 수집
- test/: 수학·서비스 보존·API 오류·서버 테스트

경로 실험(22분 우체부 예제)과 배차 실험은 별도 표시합니다.

## 공정한 비교

A는 세 차량 동시 출발, B는 0·240·480초 분산입니다.
차량·정류장·속도·정차 25초·승객 가정·관측 길이는 동일합니다.
준비구간 3주기 후 60분 관측하고 창 끝 다음 서비스까지 계산합니다.
배속은 계산된 기록을 재생하는 시계에만 작용합니다.
관측창에서 처리 건수가 달라지면 숨기지 않고 함께 공개합니다.

## 검증

19+3=22, K5 5색, 끊긴 경로 거부, 정류장 이름 변경 불변,
차량·정류장 보존, FIFO, 정확한 관측창, 배속 독립,
기관 오류, 비밀파일 접근 차단을 검사합니다.
실측 단계는 같은 지연 표본으로 반복 실험하고 평균·최악값을 보고합니다.
현재 결정적 데모를 통계적 실증으로 표현하지 않습니다.
